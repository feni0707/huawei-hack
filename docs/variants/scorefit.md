## Алгоритм

**Новое (2026-10-19, C1 — устойчивость):** (а) сторона остатка — к соседу, который скорее умрёт, по онлайн-
статистике порядка смертей (средняя доля живых моложе удаляемой; > 0.5 — умирают старые, остаток к старшему
соседу); (б) подтверждённая зона B: B кладётся только в дыры между B (иначе к границе роста), A не занимает
дыры между двумя живыми B; (в) подтверждение строже: доля смертей B − A > 0.9 (было 0.5). На 1230 тестах:
pairs +29 %, fifo +2.6 %, queue_mix +1.3 %, size_life +0.24 %, periodic +0.13 %; sorted_groups −0.03 %.

**Новое (2026-10-19): линейная оценка кандидатов вне потоков.** Вместо «best fit + ручные правила 1, 3, 4»
кандидат (по одному промежутку каждой длины + самый короткий большой) оценивается суммой 17 признаков с весами,
подобранными CMA-ES (`scripts/cmaes_weights.py`, лаба: `SF="14=6 15=0"` — теперь по умолчанию, старое — `SF="14=0 15=4"`).
Самые весомые: точное попадание (−38.8), остаток, равный ходовой длине (−203·доля), сломать дыру ходовой длины
(+107·доля), мёртвый остаток ≥ 4 м (+1050), живой остаток < 2m (+27.9), хвост без докопки дешевле кандидата
дороже 69. Парно на независимых наборах: two_phase +0.13 % (3 σ), lifo_mix +0.38 % (4 σ), alternating ≈ 0.
Ниже — описание прежних компонент (потоки и крошечная траншея не менялись; best fit/правила 1, 3, 4
работают теперь только внутри потоков или поглощены линейной оценкой).


База — **best fit**: свободные промежутки в корзинах по точной длине (< 128, кучи по адресу с ленивым удалением)
+ общая куча для больших; граничные метки для склейки за O(1); хвост траншеи используется последним;
докопка минимальная. Плюс:

1. **Сторона внутри дыры:** остаток прижимается к более молодому соседу (больший PID) — он скорее умрёт, и остаток
   сольётся. +0.02 obj.
2. **Потоки (главная идея).** Онлайн ищем признак, носители одного значения которого *умирают вместе*: для
   соседних удалений в одной пачке считаем долю совпадений признака и сравниваем с ожидаемой при независимости
   (каппа). Признаки: чётность индекса в серии равных длин, чётность PID. Если каппа ≥ 0.6, трубы делятся на
   два потока: A кладётся к левому краю «граничного промежутка», B растёт влево от правой границы роста F
   (участками по 400 м). Какая бы половина ни умерла — освобождается одна большая сплошная дыра.
   Тот, кто по статистике умирает чаще, идёт в B. Если прогноз *подтвердился* на помеченных трубах
   (смертность B − A > 0.5), B идёт сразу к границе роста, минуя дыры.
   Эффект: тест 5 0.50 → 0.94, 9 0.50 → 0.64 (UB 0.663), gen sorted_groups 0.50 → 0.79 (UB 0.83).
   *Участки (2026-10-19, вторая версия):* участки по очереди зеркальны — `[A→ ←B][B→ ←A]…`, области одного потока
   соседних участков смежны и при вымирании сливаются (sorted_groups +0.9 %, desc_groups +0.5 %, parity_flip
   +0.7 %, без проигрышей). Недозаполненный участок в конце теста — чистая потеря ≈ C/2 (в траншее ~5000 м это
   4 %, отсюда проигрыш best fit'у на pairs/periodic), поэтому участок ≤ max(200, 10·L, экономия), где экономия —
   насколько свободного внутри траншеи (без хвоста и граничного промежутка) у нас меньше, чем у «тени» без потоков.
   Тень — копия аллокатора при первой возможной метке потока (до неё раскладки совпадают), без меток; удаляется при
   T > 3·10⁶ (память). Итог: pairs +0.5…0.8 %, periodic +0.2 %, sorted_groups +0.7…1.2 %.
3. **Не «замуровывать» дыру у умирающего соседа:** штраф точному попаданию, если сосед из класса длины с
   высокой *текущей* интенсивностью смертей (доля недавних удалений / доля живых), за вычетом интенсивности
   класса самой новой трубы. Тест 10: 0.66 → 0.79.
4. **Промежутки с мёртвым остатком ≥ 4 м не рассматриваются** (остаток короче всех ожидаемых труб; только вне
   потоков; если других нет — хвост). 15: 0.947 → 0.950, 12/13/8 чуть лучше. Ранний вариант «лучшая дыра даёт
   мёртвый остаток → сразу в хвост» на части тестов two_phase разносил траншею (−23 %) — нашлось только на
   большом наборе.
5. **Крошечная траншея (< 60 м):** точное попадание (если у соседа не «часто умирающая» длина), иначе самая
   большая дыра. Тесты 2 и 3 → верхняя оценка (1.0 и 0.75); на больших тестах правило не срабатывает.

Проверка (наборы, на которых не подбиралось): **big** — seed 100–111, 384 теста, по 72 two_phase и alternating;
seed 7–9; классы устойчивости `scripts/gen_robust.py` (три фазы, удаляются только длинные, случайная половина
группы, смешанные группы) и 60 тестов «случайных групп». Итог на big: best fit obj 21.573 → scorefit 22.164;
все компоненты ≥ 0 (потоки +0.57, сторона +0.012). На классах устойчивости scorefit нигде не хуже best fit
больше чем на 0.1 % (long_die), на группах лучше на 1–2 %.

## Как мерить (быстрый стенд)

```bash
c++ -std=c++17 -O2 -DSIM -o build/sim_sf solutions/scorefit_lab.cpp # оффлайн-симулятор, без интерактора
build/sim_sf materials/tests/*.in                                     # KPI по тестам; SF="i=v ..." — параметры
for s in 1 2 3 4 5 6; do python3 scripts/gen_tests.py --seed $s --out build/gen$s --clean; \
  python3 scripts/gen_tests.py --class two_phase --count 6 --seed $s --out build/gen$s --clean; done
```

Целевая метрика: `obj = 10·two + 4·(alt + pha) + 2·(srt + per + rnd)`. **Решения принимать по большому набору
(≥ 60 тестов на класс)**: на 30 тестах класса эффекты ±0.002 — шум, а редкие провалы не видны.
Текущее на seed 1–6: obj 22.228, alt 0.957, per 0.759, pha 0.999, rnd 0.999, srt 0.791, two 0.931.
Разрыв до UB: alt 3.4 %, per 3 %, srt 4 %, two 6.4 % (из них ~3.6 % неустранимо).
alternating хаотичен: одиночное отклонение от best fit меняет итог на ±20–40 м в любую сторону — сравнивать
только средним по многим тестам.

Близкие идеи в литературе: LLAMA (Google, ASPLOS 2020) — аллокатор, группирующий объекты по предсказанному
классу времени жизни и исправляющий ошибки предсказания на лету; у нас то же, но класс — по признаку «умирают вместе».
