# Вариант A: «чистые» аллокаторные политики + мягкая сегрегация по размерам

Автор: egor (Claude), 2026-10-19. Код: `solutions/variant_a.cpp`. Инструменты: `scripts/sweep_a.py`,
`scripts/paired_a.py`, `scripts/oracle.cpp`, новый класс `short_long` в `scripts/gen_tests.py`.

## Что делает вариант A

Одно состояние (свободные промежутки со склейкой соседей) и параметризованные политики выбора промежутка:

| pol | Правило |
|---|---|
| 0 best | наименьший промежуток длины ≥ L; среди равных — самый левый (`tie=0`) или правый (`tie=1`) |
| 1 first | самый левый подходящий |
| 2 last | самый правый подходящий |
| 3 worst | самый большой |
| 4 / 5 bwl / bwr | самый левый / правый среди промежутков с запасом `len − L ≤ w`, иначе best |
| 6 sliver | best fit со штрафом `p` за остаток `1..m−1` («щепка») |

Дополнительно: сторона в промежутке (`side`: слева / справа), раздельные параметры для коротких (`L ≤ thr`)
и длинных труб (мягкая сегрегация, п. 8.4 ресерча), режим докопки (`ext=0`: труба в начало хвоста,
`ext=1`: труба прижата к новому концу траншеи). Докопка всегда минимальна и использует свободный хвост.

`solutions/variant_a.cpp` собирается двумя способами: решение (интерактивный протокол, параметры по умолчанию)
и лаборатория `-DLAB` (оффлайн-симулятор без интерактора, весь набор тестов за секунды).

## Результат

**Лучшая конфигурация в пространстве A — классический best fit** (`pol=0`, самый левый среди равных, труба к левому
краю промежутка). Именно она стоит по умолчанию. Это то же самое, что `solutions/bestfit.cpp`: open **28.3758 / 32.1**.

Проверено на 150 сгенерированных тестах каждого класса (30 seed) парным сравнением (`scripts/paired_a.py`),
значимость — разность больше 2·SE:

| Изменение относительно best fit | Итог |
|---|---|
| first fit по адресу (`pol=1`) | хуже на `random_bursts` (−0.005), ничего не выигрывает |
| last fit, worst fit | заметно хуже |
| tie среди равных: правый (`tieL=1`) | `short_long` −0.0019 (112 тестов хуже, 32 лучше), остальное шум |
| ограниченный запас (`pol=4/5`, `w=3`) | `random_bursts` −0.0045 (150 из 150 хуже) |
| штраф за «щепки» (`pol=6`, `m=2..8`, `p=1..8`) | все в пределах ±0.0005 от best fit (шум) |
| сторона `side=1` (труба к правому краю промежутка) | `alternating` −0.024, `phases` −0.0014, `random_bursts` −0.0009, но `sorted_groups` +0.017 |
| раздельные политики для коротких / длинных (`thr=7,12,20`) | в пределах шума |
| докопка `ext=1` | `alternating` −0.031, `phases` −0.035, `short_long` −0.004, **`sorted_groups` +0.096** |

Вывод: выбор промежутка по размеру/адресу уже на плато. Дальнейшее улучшение невозможно за счёт «чистой» политики
выбора промежутка; потери определяются тем, что неизвестно, какие трубы будут удалены.

## Потолок: что даёт знание будущего (оракул)

`scripts/oracle.cpp`: оффлайн-раскладка «обратного времени» (пережившие трубы укладываются плотно, затем
идём по командам с конца: удаление = укладка, укладка = освобождение; best fit). Это допустимая раскладка
для известной заранее последовательности.

| Класс (gen, 30 тестов) | best fit | оракул | UB |
|---|---|---|---|
| alternating | 0.9518 | 0.9821 | 0.9898 |
| periodic | 0.7625 | 0.7850 | 0.7877 |
| phases | 0.9985 | 0.9998 | 0.9998 |
| random_bursts | 0.9983 | 0.9997 | 0.9997 |
| sorted_groups | 0.5011 | 0.8308 | 0.8308 |
| short_long | 0.9400 | 0.9965 | 0.9970 |

Открытые тесты: оракул достигает UB почти везде (5: 0.953, 9: 0.663, 10: 0.800, 13: 0.991, 15: **1.000**).
Весь запас над best fit — это предсказание времён жизни, а не выбор промежутка. Оговорка: оракул знает,
какие именно трубы умрут; честный онлайн-потолок ниже (для `short_long` часть удалений — случайное
прореживание «полосы» коротких труб, их по-индивидуальному не угадать).

## Генераторы тестов: класс `short_long` (улучшение тестов)

Прежние классы `random_bursts` давали KPI ≈ 0.998, а реальные 11 и 15 — 0.901 и 0.948: генератор был
в разы легче реального, настраиваться на нём нельзя. Разбор тестов 11 и 15 показал две фазы:

- фаза 1 (первая половина): 80 % укладок длины 1..7, удаления только недавних труб (ранг от новейшей живой
  лог-нормальный, медиана ≈ 10), остаётся ~60 тыс. коротких труб;
- фаза 2: укладки только длины 8..40 (в 11: 8..32), 50 % удалений; ~83 % жертв — недавние длинные, ~15 % —
  равномерно из окна рождения `[0.36n, 0.5n]` (плотная «полоса» коротких труб, из неё удаляется ~35 %),
  ~1.4 % — из узкого окна около `0.17n`, остальное равномерный фон. Внутри пачек удаления независимы.

Дыры от прореженной полосы короткие (< 8), длинные трубы в них не помещаются, поэтому потолок онлайн-стратегий
для этого семейства заметно ниже UB. Класс `short_long` в `scripts/gen_tests.py` воспроизводит это семейство
с разбросом параметров; best fit на нём даёт 0.94 (как на 11 и 15).

Рекомендуемая генерация (все seed вместе, 30+ наборов): 

```bash
for s in $(seq 1 6); do python3 scripts/gen_tests.py --seed $s --count 5 --out build/gen_s$s --clean; done
for s in $(seq 7 30); do python3 scripts/gen_tests.py --seed $s --count 5 --out build/gen_big/s$s --clean; done
```

## Как воспроизвести

```bash
c++ -std=c++17 -O2 -DLAB -o build/lab_a solutions/variant_a.cpp      # лаборатория
build/lab_a pol=0 materials/tests/15.in                              # имя kpi T occ peak ub
build/lab_a pol=0 ext=1 vis=1 /tmp/small.in                          # картинка раскладки для маленького теста
python3 scripts/sweep_a.py "pol=0,1,2 side=0,1 tie=0,1" --top 10     # перебор + взвешенная цель
python3 scripts/paired_a.py --open "pol=0" "pol=0 ext=1"             # парное сравнение, значимость
c++ -std=c++17 -O2 -o build/oracle scripts/oracle.cpp && build/oracle materials/tests/*.in
```

Цель перебора `obj = (10·short_long + 4·alternating + 4·phases + 2·random_bursts + 1·periodic + 1·sorted)/22`
отражает предполагаемый состав закрытых тестов (27–30 как 15, 16–26 как 12–14) и не использует открытые тесты.

## Наблюдения для команды (направления за пределами A)

1. **Предсказание времён жизни — единственный крупный резерв** (раздел про оракул). Самые большие потери у
   `sorted_groups` (33 п.п. над best fit) и `periodic`; на `alternating` и `short_long` 3–6 п.п.
2. **Форма раскладки при росте траншеи влияет на слияние дыр.** Тривиальный `ext=1` (труба к новому концу
   траншеи, промежуток перед ней) улучшает `sorted_groups` на +0.096, хотя вредит остальным классам. Значит,
   осознанное разведение труб по «зонам» (например, разные зоны для будущих «жертв» и «выживших») может дать
   много больше и без потерь на других классах: гипотеза в работе.
3. CPU: сам аллокатор тратит ≈ 0.3 с на 200 000 команд; остальное — накладные расходы пайпов
   (в песочнице naive-решение тоже тратит ~3.4 с на тесте 15, у вас ≈ 0.4 с).

## A+: адаптивные полосы (по умолчанию включены)

Серия подряд идущих укладок равной длины; по пачке удалений после прошлой серии определяется закономерность
(индекс i%m==r, m=2..4, ≥90 % попаданий). Затем «обречённые» и «выжившие» трубы укладываются в две разные полосы,
составленные из резервируемых участков постоянного размера (`laneCells=320`), так что освободившаяся полоса
образует большую дыру, которую точно заполняет следующая группа. Включается только после подтверждённой
закономерности (`learn=1`), поэтому на alternating/periodic/phases/random_bursts/short_long результат идентичен best fit.

| Метрика | best fit | A+ |
|---|---|---|
| open Σw (из 32.1) | 28.3758 | 28.9519 |
| sorted_groups (gen, 150) | 0.5011 | 0.7934 (все 150 лучше) |
| тест 5 / 9 | 0.50 / 0.50 | ≈0.89 / ≈0.66 |

Параметры подобраны перебором `scripts/sweep_a.py` по сгенерированным классам. Проверка реальным интерактором:
WA = 0, TL = 0, CPU ≤ 0.53 с на наборах (`scripts/bench.py`).
