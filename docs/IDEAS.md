## Главный факт, на котором строятся идеи

Генератор открытых тестов удаляет почти всегда одну из **последних труб той же длины**: ранг среди живых той же
длины — медиана 0–2 на 8, 11–15. Старые короткие во 2-й фазе 15 удаляет «ходок» вниз по стеку длины
(Δ ранга: 0 — 38 %, 1 — 17 %, 2 — 7 %). Отсюда два следствия: (1) дыра от удалённой трубы длины X, скорее всего,
сразу понадобится следующей X; (2) свежая труба длины X — главный кандидат на следующее удаление этой длины.

## Идеи по приоритету

### 1. «Бронь» свежей дыры под её длину (15, 14, 12, 13) — ожидаемо самое ценное
Когда удаляется труба длины X, её дыра на K укладок (K ≈ 30–60, или пока не придёт X) бронируется: её берёт
только X (точно) или труба, оставляющая остаток ≥ m и редкого размера. На хвосте 14 это ровно паттерн
«удалили X → кладут X»: сейчас X ± 1 занимают такую дыру с остатком 1, а следующая X идёт в хвост. Во 2-й фазе 15
так же уходят остатки 1–3 м между длинными (≈ 1.1 тыс. м = +0.25 % KPI). Это мягкая версия зон для длинных
(жёсткие зоны для длинных давали 0.88 — резерв под колебания численности 33 длин).
Сигнал «бронировать или нет» — та же доля удалений «по стеку длины» (lifoHit), что гейтит зоны.
Проверка: two_phase_real, gen_robust3 (fifo/sawtooth/del_half_group — там брони быть не должно), open 14/12/13.

### 2. Модель будущего «по стеку длины» для rollout-поиска (12/13/14, класс 15)
Rollout с bootstrap прошлой истории был хуже best fit (−0.7…−1.1 %), а оракул давал +0.9 %: мешало незнание,
КТО умрёт. Теперь есть хорошая модель: удаление = выбрать длину (по частоте недавних удалений длин), ранг внутри
длины ~ Geom(0.5). Rollout H = 50–100 только при спорных решениях (разница цен кандидатов < порога), 8–16
сэмплов, best fit внутри. CPU сейчас 0.53 с — запас ×5. Начать с офлайн-проверки на 13/14/12 (`scratchpad roll2.cpp`
из прошлого эксперимента), потом на lifo/alternating.

### 3. Генератор для класса 12/13/14 с удалениями по стеку длины
Старые `alternating`/`lifo_mix` удаляют по глобальному рангу; на них решения 12/13/14-типа проверяются плохо
(так же, как старый `two_phase` не видел выигрыша зон). Сделать `scripted_lifo`: сценарные фазы (серии
«L 1 L−1 1…», циклы 5/10/5/10, «удалили X → положили X», рост без удалений), удаление — выбор длины + ранг внутри
длины Geom; калибровать по статистике рангов и по оракульным границам, как two_phase_real.
Это предусловие для честной проверки идей 1–2 и для CMA-ES.

### 5. Раскладка коротких сверх «порядка PID» (15)
Граница по коротким при зонах 12.9 тыс. м, идеальная «по длинам в порядке PID» — 12.6. Основные потери — длины
1–3 (нужно ≥ 8/L умерших подряд). Варианты: (а) не открывать отдельные зоны для 1–3, а класть их «стопками»
внутри зон длинных коротких так, чтобы ходок одной длины освобождал кусок ≥ 8; (б) участки 1–3 крупнее (ходок
режется границами участков). Сначала посчитать оракульные границы вариантов (`scratchpad seg.py`), потом делать.

### 6. Хвостовые эффекты в конце теста
На 15 ≈ 1.2 тыс. м — дыры от удалений за последнюю тысячу команд; на 14 все потери — в конце. Конец теста
неизвестен, но n ≤ 200 000: в последние ~2 000 команд до 200 000 (если тест туда дошёл) предпочитать точные
попадания в старые дыры хвосту. Прошлый «эндшпиль» (чистый best fit) был хуже — пробовать только как надбавку к
линейной оценке, и только с бронью из идеи 1.
