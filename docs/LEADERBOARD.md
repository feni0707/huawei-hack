UB — это траншея, которая ни в какой момент не длиннее суммарной длины живых труб, округлённой вверх до 20 м.
То есть **в момент пика траншея упакована без единой дыры**, а в конце пустых клеток не больше 23 м (на 15 —
23 м из 418 780). Это предел даже для оффлайн-алгоритма. Лидеры берут его на всех 15 тестах сразу.

## Почему онлайн это недостижимо (на конкретных тестах)

- **Тест 15** (и 11). Тест двухфазный: команды 1–99 999 — только трубы 1–7 м, дальше — только 8–40 м. Во
  второй фазе удаляются 8 773 «старые» короткие трубы, уложенные ещё в первой фазе: 34 865 м, примерно по 15 %
  каждой длины. Удаления идут окном, которое сдвигается назад по PID, а внутри окна — случайные трубы. Дыру от такой
  трубы (1–7 м) ни одна труба второй фазы не заполнит, если дыра не сольётся с соседней свободной клеткой.
  Чтобы в конце остались только 23 м пустоты, почти каждая из 8 773 труб ещё в первой фазе должна была лечь
  рядом с трубой, которая умрёт вместе с ней. А на момент укладки ни длина, ни PID, ни чётность, ни
  предыдущая команда не говорят, кто умрёт (проверено, см. `EXPERIMENTS.md`). У нас эти дыры — 16 тыс. м из
  22 тыс. м всех потерь (−3.6 % KPI = −0.36 балла только на тесте 15).
- **Тест 9.** Первая группа — 1000 труб длины 1, потом удаляется каждая вторая, а труб длины 1 больше не будет.
  Если раскладывать подряд, 500 дыр по 1 м мертвы навсегда, а UB требует 0. Без потерь получится, только если
  заранее угадать, какая чётность умрёт: удалений ещё не было. Правило «всегда раскладывать по чётности
  PID» мы проверили — open падает до 28.7 (тесты 4, 6, 8, 13 ломаются).
- **8, 12, 13** — траншея должна быть ровно `20·⌈пик/20⌉`. Для этого все дыры от удалений к моменту
  пика должны быть закрыты точно, без остатков, хотя будущих длин не видно.

Вывод: такие баллы получаются, только если **решение знает команды теста заранее**. Самое вероятное —
решение узнаёт открытый тест по первым командам и выдаёт заранее посчитанную оффлайн-раскладку. Тогда
на закрытых тестах 16–30 (84 балла из 116.1) это не работает: там будет запасная стратегия, и итог решат
именно закрытые тесты. Другой вариант — решение читает файл теста в обход интерактора. Это уже нарушение
правил, вопрос к организаторам.

**Честное онлайн-решение выйти на 30.757 не может.** Наши 30.013 получены без подгонки: каждое правило
проверено на 400+ сгенерированных тестах, которые в подборе не участвовали.

## Что из этого следует для команды

1. Догонять лидеров на открытых тестах **честным алгоритмом невозможно**. Подгонка под открытые тесты
   (распознавание теста и вшитые ответы) на закрытых ничего не даст, а риск дисквалификации есть.
2. Оптимизировать нужно ожидаемый балл на закрытых тестах. По весам: 16–26 (вес 4) — вероятно, классы
   12/13/14, 27–30 (вес 10) — класс 15. Проверять на `two_phase`, `alternating`, `lifo_mix`, `phases`.
3. Если очки равны, побеждает меньшее суммарное CPU — держим решение быстрым (сейчас ≈ 0.4 с на 15).
