# Gas pipeline construction — онлайн-аллокатор для интерактивной задачи NSUts

Решения задачи **«Gas pipeline construction»** (хакатон Huawei, система NSUts): оптимизация KPI в интерактивной
постановке. Репозиторий содержит финальное онлайн-решение на C++ и его порт на Cangjie, локальный стенд для прогона
и сравнения решений, генераторы тестов и подробный журнал экспериментов (что сработало и что нет).

> **English summary.** An online (interactive) 1-D allocator for a hackathon task: pipes of length 1..40 are laid
> into a trench that can only grow, and pipes are removed later by id. The score is `occupied / trench length` at the
> end. The repo has the final C++ solution (`solutions/final_online.cpp`, 30.15 / 32.1 on the 15 open tests, ~0.2 s
> CPU on the largest one), a Cangjie port, a local benchmark harness, test generators and a long experiment log.
> Documentation is in Russian. The hackathon materials in `materials/` belong to the organizers, see [NOTICE.md](NOTICE.md).

## Задача в двух словах

Интерактор по одной присылает команды (всего ≤ 200 000), следующая приходит только после ответа:

| Команда | Смысл | Ответ |
|---|---|---|
| `L` (1..40) | уложить трубу длины `L`; её PID — порядковый номер укладки | `N D`: докопать `N·20` м в конец траншеи, затем положить трубу в клетки `[D, D+L)` |
| `-K` | удалить трубу с PID `K` | `D` — её текущая позиция |
| `0` | конец | ничего |

Трубы нельзя двигать, траншея не укорачивается. Любая ошибка даёт KPI = 0 на тесте. Итог теста —
`KPI = занятые метры / длина траншеи в конце`, итоговый балл — взвешенная сумма по 30 тестам (15 открытых и 15
закрытых). Чем меньше суммарное CPU-время, тем выше место при равном балле. Полное условие — в
[docs/TASK.md](docs/TASK.md), оригинал условия (PDF) в репозиторий не входит, см. «Материалы организаторов» ниже.

## Результаты

Лучшее решение — `scorefit_guards` (в посылку идёт его переносимая копия `final_online.cpp`).

| Что | Значение |
|---|---|
| Открытые тесты 1–15 | **30.1539 / 32.1**, 0 WA/TL |
| Тривиальная верхняя оценка на них | 30.757 (достижима только при знании будущего) |
| CPU на самом тяжёлом тесте (15.in, 200 000 команд) | ≈ 0.2–0.3 с при лимите 5 с |
| Память | ≈ 18 МБ на 15.in, худший случай ≈ 50 МБ при лимите 256 МБ |
| Baseline (`naive.cpp`) | 4.91 |

Решение **честно онлайновое**: оно не распознаёт открытые тесты и не использует вшитые ответы. Вариант с вшитыми
ответами (`solutions/hybrid.cpp`) оставлен как отрицательный эксперимент — он превышает лимит CPU на тесте 15
(≈ 11 с), и отправлять его нельзя. Почему 30.757 для онлайн-алгоритма недостижимо, разобрано в
[docs/LEADERBOARD.md](docs/LEADERBOARD.md).

## Как устроено решение

Главная идея: траншея растёт лениво, потому что каждый лишний сегмент навсегда остаётся в знаменателе KPI. Всё
остальное — выбор места, в которое класть трубу так, чтобы освободившиеся позже куски склеивались в сплошные дыры,
пригодные для следующих труб.

1. **Кандидаты** — по одной дыре каждой длины и самая короткая из больших; докопка только если ничего не подходит.
2. **Оценка кандидата** — линейная функция признаков (остаток, точное попадание, «мёртвый» остаток, доли длин среди
   недавних укладок, возраст соседей и т. д.). Веса подобраны CMA-ES на сгенерированных классах и проверены на
   независимых наборах.
3. **Потоки** — онлайн ищется признак (чётность PID, номер в серии равных длин по модулю 2–5), у которого носители
   одного значения умирают вместе. Две такие группы кладутся в зеркальные участки, чтобы при вымирании одной из
   них освобождался сплошной кусок.
4. **Зоны по длинам** — когда удаляются «свежие трубы той же длины», частая длина кладётся в свою зону по стеку
   свободных слотов, и умершие подряд трубы сливаются.
5. **Страховки** — параллельно ведётся «тень» с чистым best fit. Если наша траншея длиннее неё больше чем на 10 %
   и на 1000 м, решаем как best fit, пока разрыв не закроется. Это защита от катастроф на незнакомых типах тестов.

Подробное описание, цифры и обоснования — в шапке [solutions/scorefit_guards.cpp](solutions/scorefit_guards.cpp) и в
[docs/variants/scorefit.md](docs/variants/scorefit.md).

## Материалы организаторов

Открытые тесты, интерактор, `testlib.h`, `runner.py` и PDF с условием принадлежат организаторам и в репозиторий не
включены (они в `.gitignore`). Для запуска скриптов их нужно положить в корень репозитория вручную:

1. Скачайте архив материалов со страницы задачи «Gas pipeline construction» в NSUts (тот самый архив, где лежат
   открытые тесты и интерактор). Если у вас нет доступа к задаче, запустить локальный прогон на открытых тестах
   не получится: используйте сгенерированные тесты (`scripts/gen_tests.py`, `scripts/gen_general.py`) и оффлайн-стенд
   `scripts/simc.cpp`, им материалы не нужны.
2. Распакуйте так, чтобы получилась такая раскладка:

   ```
   materials/
     interactor.cpp      # исходник интерактора, из него собирается build/interactor
     testlib.h
     runner.py
     tests/1.in … 15.in
   docs/statement.pdf    # необязательно, оригинал условия
   ```

   Готовые `interactor` (Linux ELF) и `interactor.exe` из архива не нужны, на macOS и Linux интерактор собирается
   из исходника скриптом `scripts/build_interactor.sh`.
3. Проверьте: `scripts/run_tests.sh build/final_online` должен вывести `Total: 30.15…`.

Условие задачи пересказано в [docs/TASK.md](docs/TASK.md), так что понять задачу можно и без архива.

## Быстрый старт

Нужен C++17-компилятор и Python 3 (для скриптов). Работает на macOS и Linux.

```bash
# собрать решение
c++ -std=c++17 -O2 -o build/final_online solutions/final_online.cpp

# прогнать на всех открытых тестах через официальный runner.py (взвешенный Total, максимум 32.1)
scripts/run_tests.sh build/final_online

# один тест, с причиной Wrong Answer от интерактора
scripts/debug_run.sh build/final_online materials/tests/8.in
```

Интерактор собирается из `materials/interactor.cpp` автоматически (`scripts/build_interactor.sh`); готовый
`materials/interactor` — Linux ELF и на macOS не запускается.

### Сравнение решений и генераторы тестов

```bash
# сгенерировать тесты разных классов в build/gen/<class>/
python3 scripts/gen_tests.py --clean

# таблица: open Σw, средний KPI по классам, WA/TL, CPU
python3 scripts/bench.py solutions/final_online.cpp

# потестовое сравнение двух решений
python3 scripts/bench.py --diff build/naive build/bin/final_online

# 100 «общих» тестов, не повторяющих структуру открытых
python3 scripts/gen_general.py --clean
python3 scripts/bench.py build/bin/final_online --tests build/general/*
```

Для быстрых экспериментов без интерактора есть `scripts/simc.cpp` + `scripts/simcmp.py`: около 1700 тестов за
несколько секунд. Все параметры описаны в шапках файлов.

## Соглашения для разработки

- Одно решение — один файл `solutions/<имя>.cpp`, без внешних зависимостей, чтобы его можно было отправить на NSUts.
- Решение само хранит позицию каждой трубы по PID и состояние траншеи.
- Любое изменение стратегии проверяйте `scripts/bench.py` на открытых и сгенерированных тестах; WA/TL недопустим.
- Не подгоняйте решение под открытые тесты: закрытые весят 84 из 116.1.
- После каждого эксперимента дописывайте строку в `EXPERIMENTS.md`, удачного и неудачного.
